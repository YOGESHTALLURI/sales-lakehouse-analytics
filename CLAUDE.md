# Project Instructions

Read `IMPLEMENTATION_PLAN.md`  C:\Users\DELL\OneDrive\Desktop\sales-lakehouse-analytics\implementation_plan.md before starting any work.

## Git workflow

- Never implement directly on `main`.
- Work on the feature branches defined in `IMPLEMENTATION_PLAN.md`.
- Make small, meaningful Conventional Commits.
- Run relevant tests/checks before each commit.
- Push verified commits to the feature branch regularly.
- Open a pull request into `main` only after checks pass.
- Never force-push, rewrite history, commit secrets, or commit generated runtime data.

## Architecture requirements

- PostgreSQL is OLTP only.
- MinIO stores immutable raw Parquet extracts.
- DuckDB is the analytical warehouse.
- Analytics APIs must query DuckDB, not PostgreSQL.
- All synthetic data must be generated by this repository.
- Keep Docker Compose reproducible from a clean clone.

## Working style

- Implement one planned phase/feature branch at a time.
- Do not begin the next phase until the current branch is tested, committed, pushed, and merged.
- Keep README, OpenAPI contract, and architecture documentation current.
